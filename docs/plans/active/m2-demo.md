# M2 demo: app layer, playable UI, smoke test

Status: built, reviewed, review fixes applied (2026-10-25, see "Review fixes" at the end). Spec 2026-10-25, builds on M1 (`docs/plans/active/m1-core.md`). Branch `m2-demo`, nothing committed yet.

Goal: the first playable Nice Dice on the Pages URL. Roll dice for points, buy up to five dice, level them, auto-roll, offline progress, autosave, export and import. No combos, ascension, draft or prestige yet.

## Build notes (2026-10-25)

Built by four parallel agents (store, storage, UI, e2e) and a verifier. `pnpm check` (tsc -b, oxlint, 233 unit and guard tests) and `pnpm test:e2e` (the five Playwright scenarios) are green against the Vite dev server on 5173, and `pnpm build` passes. Verified in the browser by the builders: reload persistence, the away modal, the second-tab locked screen, export and import, theme and reduce-motion switches.

Deviations from the spec above, and why:

- Store actions are module functions, not methods on the store object: `send`, `tick`, `creditOffline`, `dismissOffline`, `replaceGame`, `setUi`, `setSettings`, `setSaveStatus` in `src/app/store.ts`. `UiState` gained `save: { lastSavedAt, persisted, error, quarantined }` so the settings status line and the error banner read from the store. `startLoop()`, `saveNow()` and `boot()` take no store argument; there is one store.
- `loadSave()` returns `{ kind: 'ok'; savedAt }` and replaces the game itself (and sets `ui.save.lastSavedAt`) instead of handing the state back. `importString` and `resetGame` set the outgoing game aside under `nice-dice:replaced:<now>`, then save at once and clear `quarantined` (review fix 1).
- `saveStore` gained `remove` and an optional synchronous `sync` mirror (localStorage). Chrome aborts IndexedDB writes issued at `pagehide` or `visibilitychange` during a navigation (verified with a probe in the dev tab), so the unload save goes to the mirror synchronously through `saveSync()`, and `loadSave` takes the newer of IndexedDB and the mirror, writing a newer mirror back to IndexedDB. Every unreadable copy is quarantined before anything is written back. IndexedDB stays the save of record; backups and quarantine live only there.
- `requestAd` returns `'shown' | 'skipped' | 'error'` as this spec says. ARCHITECTURE.md still says `'done' | 'skipped' | 'unavailable'` and lacks `remove` and `sync` on `saveStore`; the docs owner should update the Platform adapter section.
- Settings persist in localStorage under `nice-dice:settings`, outside the game save, and are read at store creation. `main.tsx` applies the stored theme synchronously before the first render (review fix 5); `boot()` calls `startTheme()` first, then the tab lock, then `loadSave`.
- Import is two steps: the first click validates the string and arms a confirmation with the export textarea focused and selected, the second replaces the game (review fix 4). Reset keeps the typed `RESET` confirmation.
- `selectDieCost(id)` is named `selectDieCostText(id)` because it returns the formatted string. Die cards read one `selectDieCard(id, index)` factory under `useShallow`.
- `DieFace` keys its 300 ms nudge on the roll count (`selectRolls`), not `lastRoll.at`, because two manual rolls inside one 100 ms tick share the same `at`.
- The "estimated" note shows only when at least one whole tick (`rules.offline.tickMs`) was settled at expected value (`isEstimated` in `src/app/selectors.ts`); the sub-tick remainder every absence has is rounding, not an estimate.
- The settings button is disabled until `ui.booted` so the export string never shows the placeholder game.
- Extra test ids beyond the contract: `settings-dialog`, `settings-done`, `theme-select`, `reduce-motion-switch`, `import-result`, `import-confirm-button`, `import-cancel-button`, `save-status`, `recovery-dialog`, `recovery-restore-<index>`, `recovery-fresh`, `recovery-error`.
- Playwright: `workers: 1`, `fullyParallel: false`, `retries` 0 locally and 1 on CI, `forbidOnly` on CI, list reporter plus github on CI, `reuseExistingServer`. The spec wipes both IndexedDB names `nice-dice` (the one `platform.ts` opens) and `keyval-store` (idb-keyval's default) and waits for the localStorage mirror key `nice-dice:save` as the boot-finished signal.

Open for the owner:

- `.gitignore` needs `test-results/` and `playwright-report/` before the first commit on this branch (Playwright writes `test-results/` on every run). Not an owned path in this build.
- `playwright.config.ts` is under no tsconfig include, so `tsc -b` does not check it; Playwright transpiles it itself. Adding it to `tsconfig.node.json` would bring it under `pnpm check`.
- A reload after more than `minAwayMs` (10 s) with auto-roll locked shows the away modal explaining that the dice sat still. Correct per the spec, noisy for a developer reloading often; it could be suppressed while rolls is 0.
- The BroadcastChannel fallback (no Web Locks) has a 250 ms race when two tabs open in the same instant; the Web Locks path has none.
- Quarantine recovery is the boot-time dialog (review fix 2). Backups, set-aside and quarantined copies are not reachable from Settings while the main save is healthy; a "Backups" section there is the natural next slice.
- `navigator.storage.persist()` returns false in some embedded browsers, so the status line reads "not persisted" there.
- Not verified: the live Pages URL on a phone, the quota banner (needs a full disk). The recovery dialog is covered by `tests/e2e/recovery.spec.ts` against a seeded damaged save; unit tests in `src/app/storage.test.ts` cover both storage paths.

## App layer (`src/app`, may import core, content and any npm package, never ui or components)

- `store.ts`: a vanilla Zustand store (`createStore` from `zustand/vanilla`) holding `{ game: GameState; ui: UiState }` with `UiState = { booted: boolean; offline: OfflineSummary | null; locked: boolean; settings: { theme: 'auto' | 'light' | 'dark'; reduceMotion: boolean } }`. Actions on the store object: `dispatch(command)`, `tick(dtMs)`, `replaceGame(state)`, `setOffline(summary | null)`, `setSettings(partial)`. Export `useGameStore = <T>(selector: (s: StoreState) => T) => useStore(store, selector)` and `useShallow` re-exported from `zustand/react/shallow`. UI components select primitives or formatted strings (CLAUDE.md rule 4); provide string selectors in `src/app/selectors.ts` (`selectPointsText`, `selectPerRollText`, `selectDieCost(id)`, `selectDieLevel(id)`, and so on) so components never build objects in selectors.
- `loop.ts`: `startLoop(store)`. Fixed 100 ms accumulator (tick size from `content.rules.offline.tickMs`), driven by `requestAnimationFrame` while the document is visible and `setInterval` while hidden (rAF stops in hidden tabs). Wall-clock delta per frame is clamped: if more than `rules.offline.foregroundCatchupMs` (add it to the rules table, 60000) passed since the last frame, route the elapsed time through `applyOffline` and show the away summary instead of spinning the loop. Returns a stop function.
- `storage.ts`: IndexedDB via `idb-keyval`. Envelope `{ savedAt: number; payload: string }` where payload is `serializeState`. Keys `nice-dice:save`, `nice-dice:backup:1|5|20|60` (minute slots, rotated by age), `nice-dice:quarantine:<savedAt>`. `saveNow(store)`, `loadSave(): Promise<{ kind: 'none' } | { kind: 'ok'; state; savedAt } | { kind: 'quarantined'; reason }>`. `try/catch` on every write, `QuotaExceededError` surfaces as a non-fatal banner. An unparseable save is copied to a quarantine key and the game offers "start fresh" or "import a backup"; it is never overwritten silently. Autosave every 30 s, on `visibilitychange` to hidden and on `pagehide`. Call `navigator.storage.persist()` once after the first save. `exportString(state): string` is `ND1:` plus `lz-string` `compressToEncodedURIComponent(serializeState(state))`; `importString(text)` reverses it, validates through `parseSave`, and reports the same error kinds. Import asks for confirmation and offers export first.
- `offline.ts`: on boot, `elapsed = clamp(now - savedAt, 0, rules.offline.capMs)`; when elapsed is above `rules.offline.minAwayMs` (add, 10000) run `applyOffline` and set `ui.offline` for the modal.
- `tabLock.ts`: `navigator.locks.request('nice-dice', { ifAvailable: true }, ...)` held for the page lifetime; when unavailable set `ui.locked = true` and render the "already open in another tab" screen without starting the loop or autosave. Fall back to a `BroadcastChannel` ping where Web Locks is missing.
- `platform.ts`: `interface Platform { gameplayStart(); gameplayStop(); loadingStart(); loadingStop(); requestAd(kind: 'midgame' | 'rewarded'): Promise<'shown' | 'skipped' | 'error'>; happytime(); saveStore: { get; set; remove } }` and `webPlatform`, a no-op implementation whose `saveStore` is the idb-keyval functions. Only `src/app` touches it in M2.
- `boot.ts`: `boot(store)`: acquire the tab lock, `loadSave`, create a new game with a seed from `crypto.getRandomValues` when none, run offline, `replaceGame`, start the loop and autosave, mark `ui.booted`.
- `theme.ts`: moves the `.dark` bootstrap out of `main.tsx` and honours `settings.theme`; `reduceMotion` adds a `reduce-motion` class on `html` that CSS uses alongside `prefers-reduced-motion`.

## UI (`src/ui`, imports app, core types and selectors, content, shadcn components)

- `GameScreen.tsx`: header (title, settings button), points panel (big `N.format` value, expected per roll), `DiceBoard`, `RollControls`, `LastRoll`, footer with a credits line placeholder.
- `DiceBoard.tsx` and `DieCard.tsx`: one card per content die in order. Owned: die face SVG showing the last rolled face, level, multiplier, three level buttons (x1, x10, max) with their cost, disabled when unaffordable. Not owned but unlock satisfied: a buy button with the cost. Locked: a muted card saying what unlocks it (`nextUnlock`). Costs and multipliers are strings from selectors.
- `DieFace.tsx`: SVG die with pips for 1 to 6 (reuse the favicon geometry), a roll animation (CSS keyframes on transform only, 300 ms) that is skipped under `prefers-reduced-motion` or the `reduce-motion` class.

- `SettingsDialog.tsx`: theme select, reduce motion switch, export (textarea plus copy button), import (textarea plus confirm), reset with a typed confirmation, save status line (last saved, persisted yes or no).
- `LockedScreen.tsx` for the second-tab case. `ErrorBanner.tsx` for quota and quarantine notices.
- Mobile: single column under 640 px, `min-h-dvh`, `touch-action: manipulation` and `select-none` on tap targets, 44 px minimum targets, safe-area padding kept from M0.
- Accessibility: buttons have labels, the points value is not an `aria-live` region, dialogs are shadcn (focus trapped), reduced motion respected.

## Review fixes (2026-10-25)

Applied after the verifier's review of the first build. Every medium objection is fixed at its root with a regression test; the low ones inside the owned paths too. `pnpm check` (tsc -b, oxlint, 20 Vitest files, 254 passed, 1 skipped) and `pnpm test:e2e` (10 Playwright scenarios) are green against the dev server on 5173. Nothing committed.

1. Backups survive reset and import (medium). `rotateBackups` in `src/app/storage.ts` now copies the save being replaced (the main key read before the write) into every due slot, never the new text, so a slot always holds a game that was once the main save and the first save after a reset or import rotates the outgoing game, not the fresh one. The first save ever writes no slot; an unreadable main save never spreads into the slots; a slot is never overwritten with an older stamp. `resetGame` and `importString` first call `setAsideCurrent()`, which writes the outgoing game (when it has at least one roll) under `nice-dice:replaced:<now>` for good. The reset label now reads "Copy the export above first; it is the only way back", which is true until a restore UI exists outside the recovery dialog. Tests: `src/app/storage.test.ts` "backup slots" (five cases), "resetGame" and "importString and the game it replaces".
2. Recovery dialog (medium). `boot()` stops on `loadSave` kind `quarantined`: it lists every backup slot, set-aside and quarantined copy through `src/app/recovery.ts` (`listRecoveryCandidates`, `describeCandidate` via `parseSave`, `restoreFromKey`), sets `ui.recovery` and returns without starting the loop, autosave or the persistence request. `src/ui/RecoveryDialog.tsx` is a blocking shadcn Dialog (no close button, Escape and outside clicks ignored) with a Restore button per readable copy (stamp, rolls, points), a collapsed list of copies this version cannot read with the reason, and Start fresh. `finishRecovery(choice)` in `src/app/boot.ts` loads the copy (or a new seed), credits the time since its stamp, clears `quarantined`, saves and starts the loop; a failed restore shows its reason and keeps the dialog up. `SaveStore` gained `keys()` (idb-keyval `keys`, memory store map keys) to find the quarantine and replaced keys. The HMR dispose no longer saves while a boot is waiting on the dialog. `UiState` gained `recovery: RecoveryState | null`. Tests: `src/app/recovery.test.ts`, `tests/e2e/recovery.spec.ts` (restore a seeded 5 minute slot over a damaged main save; fresh start with no backup, quarantine copy kept, Escape refused).
3. Hidden-tab wake-ups as one absence (medium). `src/content` is not an owned path, so `foregroundCatchupMs` stays 60 s and the loop handles it instead: while `document.hidden` every gap over the threshold is credited silently (`creditOffline(dt, false)`) into a `HiddenSpan` (`src/app/offline.ts`), and on the visibility change back the whole span is reported once, measured from the game itself (rolls and `totalEarned` then and now, estimated time summed from the credits), so ticked minutes and credited minutes both count. No summary when no gap needed the offline path, so a short tab switch stays silent. `showOffline` in the store merges into a summary the player has not dismissed yet, so two laptop sleeps in a row read as one absence too. Tests: `src/app/offline.test.ts`.
4. Import confirmation (medium). `src/ui/SettingsDialog.tsx`: the Import button runs `decodeExport` and shows the reason when the string is not a save; for a valid one it arms a "Replace the current game?" step with the export textarea focused and selected (one copy away), and only `import-confirm-button` calls `importString`. Editing the string or "Keep playing" disarms. Tests: `tests/e2e/import.spec.ts`.
5. Dark-mode flash (low). `src/main.tsx` calls `applyTheme(store.getState().ui.settings)` before `createRoot`, so the loading frame paints in the stored theme; `startTheme()` in `boot()` follows later changes. The window before the bundle runs still paints the browser default; an inline script in `index.html` would close that and is the owner's call (not an owned path).
6. Tap targets (low). The settings dialog hides shadcn's 28 px close button and closes through a 44 px Done button in a footer (`settings-done`); Escape and the overlay still close it. The phone smoke test measures it after the open animation settles.
7. Smoke test asserts 0 (low). `tests/e2e/smoke.spec.ts` checks the fresh game reads `0` before rolling. Shared helpers moved to `tests/e2e/helpers.ts` (clear, seed and read the IndexedDB store and the mirror).
8. Save status clock (low). `selectSaveStatusText` is gone; `SettingsBody` selects `lastSavedAt`, `persisted` and `error` as primitives and formats them with `formatSaveStatus` against a 1 Hz `useNow()` hook (`src/ui/useNow.ts`), so the selector is pure and "Saved N s ago" keeps moving while the store is idle.

Not done, outside the owned paths (owner): `.gitignore` entries `test-results/` and `playwright-report/` (Playwright leaves `test-results/` in the root); `playwright.config.ts` in `tsconfig.node.json` include; ARCHITECTURE.md Platform adapter block (`requestAd` result union, `saveStore` with `remove`, `keys` and the optional `sync` mirror); a `docs/DECISIONS.md` entry for the localStorage mirror of the current save; raising `rules.offline.foregroundCatchupMs` if the owner prefers that over the hidden-span handling in the loop.
